# Release Guide for kubo-rs

This document describes how the cargo-dist release pipeline works and what must be configured for it to succeed.

## Overview

Releases are automated with [cargo-dist](https://github.com/axodotdev/cargo-dist). Pushing a git tag that looks like a version (e.g. `v0.1.0`) triggers the `Release` workflow, which builds binaries for all supported platforms and publishes them to a GitHub Release.

## Prerequisites

1. **cargo-dist** is installed locally (`cargo install cargo-dist`)
2. The workspace has a `dist-workspace.toml` at the repository root
3. The `release.yml` workflow exists under `.github/workflows/`

## dist-workspace.toml

Key settings:

```toml
[dist]
cargo-dist-version = "0.32.0"
ci = "github"
installers = ["shell", "powershell", "homebrew"]
tap = "homebrew-randymcmillan"
targets = [
    "aarch64-apple-darwin",
    "aarch64-unknown-linux-gnu",
    "x86_64-apple-darwin",
    "x86_64-unknown-linux-gnu",
    "x86_64-pc-windows-gnu",
]
install-path = "CARGO_HOME"
publish-jobs = ["homebrew"]
install-updater = true
allow-dirty = ["ci"]
```

### allow-dirty

`allow-dirty = ["ci"]` is **required** because we manually inject Go/MinGW setup steps into the auto-generated `release.yml`. Without this, `dist plan` fails with:

```
run 'dist init' to update the file
('allow-dirty' in Cargo.toml to ignore out of date contents)
```

## Manual Changes to release.yml

The workflow is auto-generated by `dist generate --mode=ci`, but the following steps **must** be added by hand because cargo-dist knows nothing about the Go FFI dependency.

### 1. Install Go

Add before the `Install dist` step in the `build-local-artifacts` job:

```yaml
- name: Install Go
  uses: actions/setup-go@v5
  with:
    go-version: "1.26.5"
    cache: false
```

### 2. Install MinGW (Windows)

Go CGO on Windows requires a C compiler. We use MinGW (not MSVC) because the Rust target is `x86_64-pc-windows-gnu`.

```yaml
- name: Install MinGW (Windows)
  if: runner.os == 'Windows'
  run: |
    choco install mingw -y
    echo "C:\ProgramData\Chocolatey\lib\mingw\tools\install\mingw64\bin" | Out-File -FilePath $env:GITHUB_PATH -Encoding utf8 -Append
```

### 3. Install Rust target (Windows GNU)

GitHub Windows runners ship with the MSVC toolchain by default. We must install the GNU target and switch the default toolchain so that cargo-dist links with the GNU linker.

```yaml
- name: Install Rust target (Windows GNU)
  if: runner.os == 'Windows'
  run: |
    rustup target add x86_64-pc-windows-gnu
    rustup default stable-x86_64-pc-windows-gnu
```

## build.rs Cross-Compilation Support

`build.rs` compiles `go/kubo-sys/ffi/` into a static C archive. It must allow cross-compilation for the following target/host pairs:

| Target | Host | Reason |
|--------|------|--------|
| `aarch64-apple-darwin` | `x86_64-apple-darwin` | macOS universal binary (Xcode ships both SDKs) |
| `aarch64-unknown-linux-gnu` | `x86_64-unknown-linux-gnu` | Linux ARM64 via `cross` |
| `x86_64-pc-windows-gnu` | `x86_64-pc-windows-msvc` | Windows GNU toolchain on MSVC runner |

The script checks `TARGET != HOST` and panics unless both OSes match (Darwin ↔ Darwin, Linux ↔ Linux, Windows ↔ Windows).

## Triggering a Release

1. Ensure `main` is green and all submodules are up to date.
2. Bump the version in `Cargo.toml`.
3. Commit and push.
4. Tag:
   ```bash
   git tag v0.1.5
   git push origin v0.1.5
   ```
5. The `Release` workflow starts automatically.

## Troubleshooting

### `failed to run go version`: NotFound

**Cause:** Go is not installed on the cargo-dist runner.  
**Fix:** Add the `actions/setup-go@v5` step to `build-local-artifacts` in `release.yml`.

### `kubo-rs FFI build script does not support cross-compilation`

**Cause:** `build.rs` panics because `TARGET != HOST` and the OS pair is not in the allow-list.  
**Fix:** Update `build.rs` to allow the specific target/host pair (e.g. add `both_windows`).

### `unresolved external symbol ___chkstk_ms`

**Cause:** Go compiled the c-archive with MinGW/gcc, but Rust is linking with MSVC's `link.exe`. The object files contain MinGW-only symbols.  
**Fix:** Switch the Windows target from `x86_64-pc-windows-msvc` to `x86_64-pc-windows-gnu` in `dist-workspace.toml`, and install the GNU Rust toolchain + MinGW in `release.yml`.

### `run 'dist init' to update the file`

**Cause:** cargo-dist detects that `release.yml` has been manually edited and refuses to run.  
**Fix:** Add `allow-dirty = ["ci"]` to `dist-workspace.toml`.

## Verifying a Release Locally

You can dry-run the dist plan without pushing a tag:

```bash
dist plan
```

To regenerate CI files after changing dist config:

```bash
dist generate --mode=ci
```

Remember to re-apply the manual Go/MinGW/Rust steps after regenerating.
